# Phase 21 — npm Local Development Compatibility

## Outcome

LifeLink can now be installed and run from a local checkout with standard npm commands. The project keeps the managed-hosting package-manager metadata required by its preview environment, while adding a reproducible `package-lock.json` and npm-compatible scripts for local development.

## Changes

| File | Change |
| --- | --- |
| `package.json` | Updated `dev` and `start` to use cross-platform `cross-env`; added `verify`; added a root npm `overrides` section; removed development-only packages that caused npm peer-resolution failures. |
| `package-lock.json` | Generated by a clean npm installation for repeatable local installs. |
| `vite.config.ts` | Removed the unused JSX-location plugin that only supported an incompatible Vite peer range and was not part of LifeLink runtime behavior. |
| `README.md` | Added local npm installation, environment, command, database, OAuth, managed-platform, and security guidance. |

## Local Setup Reminder

Developers must create their own private `.env` file for local MySQL, session, and optional integration settings. Production or platform credentials must never be copied from deployment into a local checkout. Google OAuth needs a public HTTPS callback URL, and the managed Maps proxy or platform fallback requires its own hosting configuration.

The application’s controlled Mumbai directory remains mock-only in local development and production. Its entries and reference markers do not represent real clinicians, availability, or patient location.
